# Migrating to sitemapr 0.4.0

This guide covers upgrading from **0.3.4 to 0.4.0**. The release changes how
pages are supplied and removes public types and methods. Update callers and
your dependency requirement/lockfile together; compatibility aliases are not
provided. Python 3.10 or later is still required.

## Changes at a glance

| In 0.3.4 | In 0.4.0 | Action |
| --- | --- | --- |
| `SiteMapr(base_url, pages=pages)` | `SiteMapr(base_url)` | Move `pages` to each `save()` call. |
| `sitemap.save(output)` | `sitemap.save(output, pages=pages)` | Supply a page iterable explicitly. |
| `list[Param]` for path/query parameters | `dict[str, list[str]]` | Replace each `Param` with a name-to-values entry. |
| `SiteMapUrl(loc=url, ...)` | `Page(path=url, ...)` as save input | Replace imports and construction of URL records used for saving. |
| `sitemap.iter_urls()` | Removed | Use `save()` for file output; there is no public URL-iteration replacement. |
| XML-escaped query separators in callback URLs | Raw query separators | Update callback matching and remove manual XML escaping. |
| Empty parameter lists are skipped during expansion | Any empty value list suppresses the page | Omit an optional parameter entirely when it should not restrict output. |
| Nonpositive `chunk_size` accepted | Raises `ValueError` | Use a positive integer; the default remains `50000`. |

## 1. Move pages to the save call and replace Param

Before, with 0.3.4:

```python
from pathlib import Path
from sitemapr import Page, Param, SiteMapr

output = Path("sitemaps")
output.mkdir(exist_ok=True)

pages = [
    Page(
        path="/posts/{id}",
        path_params=[Param(name="id", values=["1", "2"])],
        query_params=[Param(name="lang", values=["en", "ko"])],
        priority="0.7",
    ),
]
sitemap = SiteMapr("https://example.com", pages=pages)
sitemap.save(str(output))
```

After, with 0.4.0:

```python
from pathlib import Path
from sitemapr import Page, SiteMapr

output = Path("sitemaps")
output.mkdir(exist_ok=True)

pages = [
    Page(
        path="/posts/{id}",
        path_params={"id": ["1", "2"]},
        query_params={"lang": ["en", "ko"]},
        priority="0.7",
    ),
]
sitemap = SiteMapr("https://example.com")
sitemap.save(output, pages=pages)
```

Both examples produce the same four URLs and priorities. Parameter names must
be unique dictionary keys, and values remain lists of strings. Omit
`path_params` or `query_params` when a page does not need them.

`SiteMapr` now retains configuration only. Pass pages on every save, including
when reusing the same instance. Lists can be reused; a generator is consumed
once, so create a new generator for another save. The output directory must
already exist, and `save()` now accepts a `Path` as well as a string.

## 2. Replace SiteMapUrl and review iter_urls callers

Use `Page(path=url, ...)` for concrete URLs, keeping the same `lastmod`,
`changefreq`, and `priority` values. `path` accepts a relative path such as
`/posts/1` or an absolute HTTP(S) URL such as `https://example.com/posts/1`.
An absolute URL is not prefixed with `base_url`.
Resolved metadata is validated during saving. If you previously caught priority
validation errors around `SiteMapUrl(...)`, handle errors from `save()` or
`asave()` as well; constructing a `Page` does not validate the priority range.

For example, using the `sitemap` and `output` from the updated example:

```python
pages = (
    Page(path=f"https://example.com/posts/{post_id}", priority="0.7")
    for post_id in range(100000)
)
sitemap.save(output, pages=pages)
```

If an `iter_urls()` call feeds a custom file writer, pass its page definitions
directly to `save()` instead. If it is used for another purpose, such as
inspecting expanded URLs in memory, that integration needs to be redesigned:
0.4.0 does not expose a resolved-URL iterator. Do not replace it with private
methods or internal URL types.

For async sources, the new `await sitemap.asave(output, pages=async_pages)`
accepts an async iterable yielding `Page` objects. Convert records to pages as
they arrive to avoid collecting the source in memory. Callers own input
resources: manage database cursors with their context managers, and use
`contextlib.aclosing` for async generators that need explicit cleanup on
failure or cancellation. Saving closes its output handles, but partial files
may remain; publish output only after saving completes successfully.

## 3. Review callback URLs and XML escaping

Metadata callbacks retain the signature `(loc, path_params, query_params)` and
may return a metadata value or `None`. The `loc` argument now contains the raw
resolved URL. For example:

- Before: `https://example.com/posts/1?lang=en&amp;sort=asc`
- After: `https://example.com/posts/1?lang=en&sort=asc`

Update callbacks that compare, split, or look up the escaped form. Remove
manual **XML** escaping from URL and metadata inputs; the writer escapes them
when producing XML. For example, pass `?lang=en&sort=asc`, not
`?lang=en&amp;sort=asc`, or the literal `&amp;` will be escaped again.
Normal URL percent-encoding still applies; this change only concerns XML
escaping. Parameters supplied through `query_params` are URL-encoded for you.

## 4. Review empty parameters and chunk sizes

An empty dictionary means there are no parameters to expand. An empty value
list, such as `query_params={"lang": []}`, now means there are no valid
combinations, so that page produces no URLs. If an empty application filter
means “include the page without this filter,” leave that key out of the
dictionary. Every placeholder in `path` still needs a corresponding value.

Both save methods reject `chunk_size <= 0` before consuming any input or
creating files. Use a positive integer if configuring this value explicitly.

## Verify the upgrade

1. Remove imports of `Param` and `SiteMapUrl`, constructor `pages` arguments,
   and calls to `iter_urls()`. Check that every save supplies `pages=`.
2. Generate a representative sitemap in an empty output directory. Parse the
   XML and compare URL counts, order, and metadata, including pages with query
   parameters and metadata callbacks.
3. Check the intended behavior for empty parameter lists and repeated saves
   from a generator. Exercise source failure and cleanup if using a database
   or async source.
4. Generate enough URLs to cross your chunk boundary and verify the index
   links before publishing the output.

The default chunk size, single-file `sitemap.xml`, split `sitemap-0.xml`
filenames, and sitemap index structure remain unchanged. Path/query
combinations, constant metadata, and metadata callbacks remain supported.
